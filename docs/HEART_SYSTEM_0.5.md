# 0.5 하트 관계 시스템

기준 소스는 `D:\CampusRomance_VN\renpy_project\game`입니다. 원고 대사·선택 문구는 바꾸지 않았습니다. 수정 전 백업은 `D:\CampusRomance_VN\backups\heart_system_20261108_212618`에 있습니다.

## 표시와 선택 보상

프로필은 빨간 하트 **해피 호감도**, 검은 하트 **배드 수치**를 각각 0–100으로 표시합니다. 기존 `affection`과 `trust`는 구세이브·기존 호출 호환을 위해 그대로 유지합니다. `trust`는 새 프로필이나 선택 알림에 표시하지 않습니다.

- 원고의 `affection` 또는 `trust` 보상 1점은 빨간 하트 5점입니다. 음수 효과는 빨간 하트를 줄입니다.
- 아래 명시된 로만 지원 카운터 1점은 빨간 하트 5점입니다.
- 아래 명시된 로만 의존·위험 카운터 1점은 검은 하트 5점입니다.
- 한 선택의 같은 색 효과를 합친 뒤 0–100으로 제한하며 알림은 실제 증감만 표시합니다. 100에서 추가 보상을 받아도 가짜 `+5` 알림이 나오지 않습니다.
- 배드 데이터가 없는 공통 선택이나 다른 인물의 선택에 검은 하트를 추정해서 붙이지 않습니다.

| 인물 | 빨간 하트로 연결되는 지원 카운터 | 검은 하트로 연결되는 위험 카운터 |
| --- | --- | --- |
| 로만 | `roman_mutual_respect`, `roman_mutual_understanding`, `roman_creative_autonomy`, `roman_relationship_balance` | `roman_unrealistic_promise`, `roman_reassurance_dependency`, `roman_approval_dependency`, `roman_dependency_risk` |
| 시아·다림·오므·하린 | 현재 명시 카운터 없음. 기존 호감/신뢰 선택 효과는 빨간 하트로 연결 | 현재 명시 카운터 없음 |

`roman_shared_reading`, `roman_reassurance` 등은 기존 원고 상태를 유지하며 엔딩 지원 4종에 임의로 추가하지 않았습니다. 실제 선택 효과 처리는 `story_apply()`와 `relationship_apply()`를 통합니다. 폰 대화의 기존 재실행 방지 검사를 먼저 거칩니다.

## 로만 엔딩 판정

UI의 빨간 하트 총점과 원고의 지원 누적은 구분합니다. 공통 루트의 호감 총점을 5로 나눠 지원 누적으로 쓰지 않습니다.

`heart_route_scores("roman")`은 다음 두 원시 단위 값을 반환합니다.

- `D`: 위험 카운터 4종의 누적 합. 검은 하트는 이 원고 위험의 5배를 표시합니다. UI 상한 100에 도달해도 엔딩용 누적을 잘라내지 않습니다.
- `P`: 지원 카운터 4종의 누적 합 + 현재 빨간 하트가 50 이상일 때 보너스 1. 이전의 숨은 `trust >= 50` 보너스를 보이는 빨간 하트로 대체했습니다.

마지막 선택의 원고 기준은 그대로입니다.

| 마지막 경계 선택 내부값 | 결과 |
| --- | --- |
| `respect` | 누적 위험이 높아도 회복을 허용하여 해피 |
| `negotiate` | `D >= 4`이면서 `D > P + 2`일 때만 배드 |
| `surrender` | `D >= 4`이면서 `D >= P`일 때만 배드 |

따라서 마지막 C 선택 하나만으로 저위험 진행을 강제 배드로 만들지 않습니다. 이 수치 기준은 원고의 정성 조건을 실행 가능하게 정한 기존 구현 기준이며, 하트 전환에서 변경하지 않았습니다. 순수 함수 `roman_r06_select_ending(D, P, boundary)`는 그대로 경계값 검사가 가능합니다.

## 저장·불러오기·되돌리기

`red_hearts`, `black_hearts`, `heart_schema_version`은 일반 Ren’Py 저장/되돌리기 상태입니다. 하트 보상 이력을 `persistent`에 쓰지 않습니다.

1. 기존 1점 단위 세이브는 원래의 `relationship_scale_version` 변환을 먼저 수행합니다.
2. 하트 스키마가 0이면 빨간 하트를 `affection + trust + 지원 카운터 합 × 5`, 검은 하트를 `위험 카운터 합 × 5`에서 복원하여 각각 0–100으로 제한합니다. 과거 점수의 상한에 의해 사라진 보상 이력까지 추정하지는 않습니다.
3. 점수 맵 두 개와 스키마 마커를 함께 교체합니다. 현재 선택의 점수·카운터를 적용하기 **전에** 변환하므로 현재 보상을 중복 합산하지 않습니다. 마커가 1이면 다시 복원하거나 추가 보상하지 않습니다.
4. 선택의 카운터·하트·선택 로그는 같은 되돌리기 저장소에 남습니다. 롤백 후 다시 고른 보상이 이전 진행 위에 누적되는 영구 보상 장부를 만들지 않습니다.

세이브 JSON에는 기존 `campus_relationship` 요약을 보존하고 `campus_hearts` 요약을 추가합니다. 메인 메뉴 프로필은 이어하기와 같은 최신 슬롯의 요약을 읽습니다. 이전 버전 슬롯에는 로만 카운터 요약이 없으므로 검은 하트를 임의의 0으로 표시하지 않고 `— / 100`으로 표시합니다. 그 슬롯을 불러와 다시 저장하면 정확한 하트 요약이 생깁니다. 메뉴에서 세이브를 강제로 불러오거나 사용자 저장 파일을 다시 쓰지 않습니다.

## 비밀 메모와 화면

공식 비밀 메모는 이미 실제 개인 이벤트·원고 진행·엔딩 완료로 해금하고 있었으며 숨은 신뢰 수치 조건이 없습니다. 이 기준을 유지합니다. 기존 `persistent.profile_secrets`와 발견 기록은 삭제하지 않으며 병합은 합집합입니다. 로만은 개별 루트 진입/실제 R03 완료, 다른 인물은 기존 개인 이벤트·약속 기록을 사용합니다.

프로필 관계 패널은 기존 위치 `(1003, 866)`에서 높이만 78로 조정했습니다. 두 게이지와 숫자, 알림은 정식 `CAMPUS_BODY_FONT`를 사용합니다. 하트는 기존 `images/ui/spring/heart.svg`의 경로를 재사용한 `images/ui/hearts/red.svg`·`black.svg`입니다. 소프트웨어 렌더에서도 사각형 마스크가 보이지 않도록 채워진 SVG를 직접 표시합니다. 헤더 제목과 ‘만난 사람들!’ 버튼은 상단 탭의 중앙 y=98에 맞췄습니다.

화면 확인용 ID는 `profile_red_value`, `profile_black_value`, 각 색의 `_caption`, `_icon`, `_track`, `_gauge`입니다. 게이지가 0이면 채움 요소는 생략합니다. 알림 ID는 `feedback_delta_<인물>_red`, `feedback_delta_<인물>_black`입니다.

## 다른 루트 확장

`systems/heart_system.rpy`의 `HEART_COUNTER_RULES[인물]["red"/"black"]`에 **원고에 명시된** 지원/위험 카운터를 추가합니다. 해당 카운터의 `default`를 선언하고 기존처럼 `story_apply(..., counters={카운터: 원시증감})`로 변경하면 하트가 함께 변합니다. 같은 효과를 카운터와 직접 하트 양쪽에 중복 작성하지 않습니다.

카운터가 필요 없는 명시 보상은 아래 API를 사용합니다.

```renpy
$ story_apply("고유_선택_ID", hearts={"sia": {"red": 1, "black": 0}})
```

`hearts` 값은 5배 하기 전 원시 단위입니다. 기존 `affection`/`trust` 효과가 있으면 그것도 빨간 하트에 합쳐집니다. 각 루트 엔딩에서는 `heart_route_scores(인물)` 또는 해당 원고의 별도 순수 판정 함수를 사용하고, 프로필 총점과 원고 카운터 단위를 혼동하지 않습니다. 이미 배포된 버전에 새 카운터를 소급 도입할 때는 스키마를 올리고 기존 상태에서 정확히 한 번 복원하는 변환을 별도로 추가해야 합니다.
