# 휴대폰 시간·시점·가독성 0.5

휴대폰은 실제 시계 대신 대본의 장면 시간을 사용합니다. CH01–CH07, 로만 R01–R06, 시크릿의 14개 구간을 등록했습니다. 기존 폰 수동 열기, 알림 게이트, 기록과 저장·불러오기, CH07 인사 중복 수리는 유지합니다.

## 화면

1920×1080 기준 기존 줌 0.74에서 0.88로 바꿨습니다. 실제 폰은 580.8×895.84, (650,18)에 표시되어 전체가 약 18.9% 커집니다. 버튼 글씨의 명시적 가로·세로 중앙 정렬과 한국어 본문 폰트를 유지합니다. 채팅 목록의 이름·미리보기·시각 열은 폰 폭 안으로 정리했습니다.

폰을 보면서 하는 독백은 아래쪽 (60,940), 1800×126의 전용 대사창에 표시합니다. 폰 끝 y=913.84와 겹치지 않습니다. 폰 답장 선택지는 내부 스크롤 영역에 있으며 일반 대사창 선택지로 바꾸지 않습니다.

## 시간과 날짜

- `systems/phone_timeline.rpy`: 대본 시각과 시점 API
- `data/phone_ui.json`: 에피소드별 기본값, 장면·원고 시간 cue, 옛 저장 위치 복구 표
- `phone_timeline_enter(episode, scene)`: 장면 시작 시 날짜·시각 설정 및 주인공 시점 복귀
- `phone_timeline_cue(episode, cue)`: 원고에 명시된 시간 경과 반영
- `phone_timeline_set(day_id, date, time, day_index, episode)`: 직접 연출용 API

시각이 명시된 장면은 그 값을 사용합니다. 오전·오후·밤만 적힌 구간은 원고 흐름에 맞는 연출 기본값을 사용합니다. 실제 월일이나 요일을 확정하지 않으며, 「축제 D-7」, 「축제 전날 D-1」, 「축제 다음날」, 「문학 낭독회 당일」처럼 이야기 안의 날짜로 구분합니다. `day_index`는 순서·어제 표시에 쓰는 내부 값이며 실제 달력 날짜가 아닙니다. 「며칠 뒤」의 정확한 일수는 원고가 확정하지 않은 값입니다.

메시지는 작성 당시 `time`, `date`, `day_id`, `day_index`를 저장합니다. 다음 날이 되어도 이전 기록을 지우거나 시각을 다시 쓰지 않습니다. 대화에는 오늘·어제·해당 날짜 구분자가 표시됩니다. 방을 다시 열 때 챕터 1의 21:14로 되돌아가지 않습니다.

## 로만의 휴대폰

`phone_perspective`는 저장·롤백되는 현재 휴대폰 주인입니다. 기본값은 `mc`입니다.

- `phone_perspective_set("roman")`: 로만 시점. 로만의 메시지는 오른쪽, 주인공 메시지는 왼쪽입니다.
- `phone_perspective_set("mc")`: 플레이어 시점 복귀
- `phone_perspective_label()`: 「로만의 휴대폰」 또는 「내 휴대폰」

이름표만 바꾸는 방식이 아닙니다. 말풍선 방향, 받은 메시지 읽지 않음 처리, 연락 상대 이름과 프로필까지 해당 시점으로 바꿉니다. 원고의 `[POV] 로만` / `[POV END]` cue를 연결하고 새 장면에서 복귀합니다. 로만 시점에서도 독백과 미전송 초안은 메시지로 발송하지 않습니다.

R03 SC04는 직전 SC03에서 주인공이 보낸 두 문장을 로만 입장에서 다시 읽습니다. 같은 날짜·같은 장면·같은 두 원문에 한해서 기존 기록을 재참조합니다. 다른 날짜나 장면의 반복 문장은 숨기지 않습니다. 현재 대사는 `phone_last_key`에 해당하는 실제 말풍선에서 표시합니다.

## 저장 호환과 재생성

새 저장은 정확한 대본 시간과 시점을 유지합니다. 이전 저장은 현재 Ren'Py 문장 위치를 등록 표와 대조해 시간·시점을 보완합니다. 이전 기록의 날짜나 메시지는 바꾸지 않습니다. 기존 수동 알림 게이트, AFM 제한, 재생 선택지 보호와 0.4.1 CH07 복구 함수는 그대로 유지합니다.

0.4.1의 실제 폰 저장을 불러와 새 cue 행 때문에 메시지 키의 줄 번호가 바뀌는 경우도 검사했습니다. 불러오기 복귀 중인 현재 메시지의 발신자·문장·챕터/파일이 기존 live key와 같으면 그 키를 참조하며, 정상 진행의 반복 메시지는 생략하지 않습니다. 이전 11개 기록의 키·날짜·시간과 선택/점수를 정확히 유지한 채 복귀하는 것을 실제 저장으로 검증했습니다.
