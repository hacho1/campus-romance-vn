# SD 이벤트 전체 컷 제작·삽입 가이드

현재 SD 장면은 **이벤트 전체를 완성한 일러스트 한 장**을 표시하고, 반응이 달라질 때 다음 완성 컷으로 교체합니다. 인물별 SD 파일을 모아 배치하거나 아틀라스에서 잘라 합성하지 않습니다. 표정·시선·손짓·입모양·인물 간 위치는 각 그림 안에서 완결하세요.

CH01~CH03의 **12개 이벤트, 33개 변형 컷**은 2026-11-04 준비된 최종 그림을 `game/images/sd_events/`에 모두 삽입했습니다. 게임용은 1920×1080 무손실 WebP이며 원본·AI4x 확대본은 `artwork/sd_events/final/`에 보존합니다. 삽입·검증 기록은 [SD 삽입 기록](../artwork/sd_integration_20261104/README.md)에 있습니다. 아래 명세는 추후 교체할 때도 사용합니다. 등록된 출연자는 장면의 맥락이며, 모두를 매 컷에 넣어야 한다는 뜻은 아닙니다. 특히 9명 장면은 주요 인물을 크게 골라 그려도 됩니다.

## 1. 파일 규격과 먼저 넣을 한 장

- 캔버스: **1920×1080, 16:9**. 변형끼리 크기와 주요 배치를 맞춥니다.
- 형식: 정적 **WebP 또는 PNG**. 파일마다 완성된 한 컷을 저장합니다.
- 저장 폴더: `D:\CampusRomance_VN\renpy_project\game\images\sd_events\`.
- 기본 이름: `<이벤트ID>_<두 자리 변형번호>.webp`.

예를 들어 라이벌 첫 자기소개 컷을 `ch02_rival_introduction_01.webp`로 저장하면 코드 변경 없이 사용합니다. 같은 이름의 `ch02_rival_introduction_01.png`도 자동으로 찾습니다. 등록표에 적힌 확장자를 먼저 확인하므로 기본 등록 상태에서 WebP와 PNG가 둘 다 있으면 WebP가 우선입니다.

이미지 전체를 `fit="contain"`으로 넣어 비율을 유지하고 자르지 않습니다. 다른 화면비는 여백이 생길 수 있으므로 16:9로 준비하세요. 투명 인물·소품 그림은 단순한 파스텔 바탕 평면 위에 표시되며, 배경까지 완성한 불투명 일러스트도 사용할 수 있습니다. 투명 파일은 알파 채널을 보존해 내보내세요.

## 2. 그림의 안전 영역과 표현 기준

좌표는 1920×1080 가상 화면 기준입니다. **얼굴·눈·입·중요한 손짓과 핵심 소품은 y≤740 안에** 두세요. 기존 화자 명패는 y=771, 대사창은 y=814부터 시작합니다. 아래쪽에는 대사창에 가려져도 되는 배경·옷자락·여백을 배치합니다. 특정 손짓이 사건의 핵심이면 손도 안전 영역에 포함합니다.

실제 대사, 화자 이름, 선택지, 채팅 내용을 그림에 넣지 마세요. **대사는 기존 Ren'Py 대사창에서만** 표시합니다. 인물의 입모양과 표정은 그림에서 표현하되 말풍선으로 발화를 굳히지 않습니다. 만화적 동작선·충격 표시처럼 말이 아닌 효과는 컷 안에 그릴 수 있습니다.

파스텔 중심의 단순한 배경, 화이트·크림 여백, 읽기 쉬운 인물 크기를 유지합니다. 과한 꽃·장식·소품으로 얼굴과 제스처를 가리지 마세요. 주인공의 성별·외형을 정하지 않으므로 주인공의 얼굴, 몸, 손, 뒷모습, 실루엣을 그리지 않습니다. 등록된 익명 방문객은 주인공과 별개입니다.

선택 메타데이터 `overlay_caption`은 네이티브 UI로 표시합니다. 이미지에 자막을 합성하지 마세요. 현재 음료수 사건 03의 자막은 y=684 부근 중앙에 나오므로 그 자리에 핵심 얼굴·손짓을 피합니다.

## 3. 등록표와 누락 파일 처리

원본 등록표는 [sd_events.json](../renpy_project/game/data/sd_events.json)입니다. `chapter`, `scene`, `title`, `type`, `cast`, `layout`, `variants`와 각 변형의 `image`, `description`을 확인하세요. `type`의 A~D는 현재 등록 분류 코드이며 추가 파일 분할 지시가 아닙니다.

아래 제작 명세의 파일 경로는 `game/` 기준입니다. 그대로 파일을 넣으면 됩니다. 파일명을 바꾸거나 변형을 추가할 때만 등록표의 해당 `image`나 `variants`를 함께 갱신하세요. ID·기존 변형번호는 저장 데이터가 참조하므로 다른 사건에 재사용하지 마세요.

요청한 변형의 WebP·PNG가 모두 없으면 **그 변형의 제목·인물·구도·설명·필요 경로가 적힌 자리표시자**를 보여 줍니다. 03이 없다고 01을 대신 보여 주지 않습니다. 미등록 변형도 그 번호의 자리표시자로 처리하므로 다른 감정의 컷으로 오해시키지 않습니다.

## 5. 대본 연결 API

이미지를 넣는 작업에는 대본 수정이 필요하지 않습니다. 연출 담당자는 [sd_event_system.rpy](../renpy_project/game/systems/sd_event_system.rpy)를 기준으로 다음 API를 사용합니다.

| API | 동작 |
| --- | --- |
| `sd_event_start(event_id, variant="01", transition=None)` | 일반 스탠딩 상태를 보관하고 지정 이벤트의 완성 컷을 엽니다. |
| `sd_event_change(variant, transition=None)` | 같은 이벤트의 변형을 교체합니다. 같은 번호를 다시 지정하면 재전환하지 않습니다. |
| `sd_event_end(mode=None, cast=None, transition=None, restore=True)` | 전체 컷을 닫고 보관한 일반·감정 모드 및 스탠딩 상태로 돌아갑니다. |

예를 들어 `sd_event_start("ch02_rival_introduction", "01")`로 시작해 기존 대사를 진행하고, 반응이 바뀌는 대사 사이에서 `sd_event_change("02")`, `sd_event_change("03")`으로 교체한 뒤 `sd_event_end()`로 마칩니다. 여러 변형을 상호작용 없이 연속 호출하면 중간 컷을 읽을 구간이 없으므로 실제 대사 위치에 나누어 연결하세요.

기본 디졸브는 등록표 `settings.transition`의 **0.22초**입니다. 권장 범위는 **0.15~0.35초**이며 각 호출의 `transition` 인자로 덮어쓸 수 있습니다. `transition=0`은 즉시 교체합니다. 화면 전환 설정이 꺼져 있으면 디졸브를 생략합니다. 설정값은 저장된 `sd_event_dissolve`에도 들어가므로 기존 저장을 불러오면 저장 당시 값이 남을 수 있습니다.

현재 이벤트 ID는 `sd_event_current`, 변형은 `sd_event_variant_id`로 저장합니다. 시작 직전의 일반 모드·출연자·표정·위치·방향도 별도로 보관하며, 기본 종료는 이를 복원합니다. `mode`·`cast`로 돌아갈 구성을 지정할 수 있고 `restore=False`는 보관한 스탠딩을 복원하지 않습니다. 새 장면·채팅·챕터로 넘어가는 정리는 런타임 연결부가 처리합니다.

기존 일반 스탠딩의 8개 표정 파일과 자리표시자는 유지합니다. SD에서는 개별 스프라이트의 표정·좌표·반전·점프를 조합하지 않습니다. 이전 `story_faceoff`·SD 위치 계산 등은 과거 저장 호환용으로 남은 코드이므로 새 SD 장면 제작에 사용하지 마세요. 새 컷에서는 표정·손짓·코미디 반응이 바뀔 때 완성 파일의 변형을 교체합니다.
