## 화면 구성

갤러리는 COMMON / ROMAN / SIA / DARIM / OMU / HARIN / SPECIAL / ENDING 탭을 사용합니다. COMMON에는 공통 LD, 각 히로인 탭에는 등록된 CH03·CH04 개인 LD가 들어갑니다. HARIN는 표시 이름이며 기존 내부 캐릭터 ID `lumi`를 유지합니다. SPECIAL은 실제로 본 SD 이벤트의 변형 컷과 기존 데모에서 수집한 첫 회의 메모를 분리해 보여 줍니다. ENDING은 기존 15개 엔딩과 연결될 미래 그림 슬롯이며, 이번 작업으로 엔딩이나 엔딩 CG를 새로 해금하지 않습니다.

수집한 그림만 썸네일과 전체 보기에서 표시합니다. 잠긴 슬롯은 실제 파일이 있어도 그림을 불러오지 않습니다. 전체 보기의 이전/다음은 현재 탭에서 수집한 항목만 순환합니다. H로 안내를 숨기고 Esc로 닫습니다. 등록된 회상 라벨은 현재 모두 비어 있으며, 회상 재생은 아직 구현된 기능으로 표시하지 않습니다.

CH04부터 같은 장면의 표정 차이는 썸네일 한 칸으로 묶습니다. 로만(기본→수줍음), 시아(태블릿→속마음), 다림(기본→미소), 오므(사진 정리→미소), 하린(모형 작업→당황)을 적용했습니다. 전체 보기에서 그림 클릭, Space, Enter 또는 우측 상단의 **표정 바꾸기** 버튼으로 실제 본 컷만 순환합니다. 0.30초 디졸브로 부드럽게 겹쳐 바뀌며, H로 안내를 숨겨도 그림 클릭·키 입력은 작동합니다. 좌우 방향키와 이전/다음 장면 버튼은 다른 장면으로 이동하며 새 장면의 첫 수집 컷부터 표시합니다. 미수집 표정은 갤러리 조작으로 해금되지 않습니다. 예전 기록에 두 번째 표정만 있어도 해당 장면 한 칸이 열립니다.

오므 CH04 SC06-D는 초반 스탠딩 대화 후 `ch04_private_omu.png`를 표시합니다. **오므의 사진** 선택지에서는 첫 그림을 유지하고, 세 답변 중 어느 것을 고르든 첫 반응 대사 전에 `ch04_private_omu_smile.png`로 0.38초 디졸브 전환합니다. 두 번째 그림은 개인 이벤트 종료까지 유지합니다. 원본 이미지는 가공 없이 보관하며, 갤러리에서는 OMU 탭의 한 칸으로 묶습니다.

오므 적용은 세 선택지·저장/불러오기·갤러리 실행 검사 4개(검증문 59개)와 Lint를 통과했습니다. [오므 일러스트 적용 검증 기록](../tests/omu_cg_20261107/README.md)에 수정 파일·화면·백업 위치를 정리했습니다.

## 그림 제작·교체

1. 1920×1080, 16:9 PNG 또는 WebP 완성 그림을 준비합니다. 권장 형식은 등록표의 WebP이며, 같은 이름의 `.png`도 자동으로 찾습니다.
2. 위 경로대로 `game/images/cg/`에 넣습니다. 파일명이 달라지면 `game/data/cg_registry.json`의 해당 `image`만 수정합니다.
3. 일반 LD의 얼굴·중요한 손짓은 y=100~740에 배치합니다. 하단 이름표는 y=771, 대사창은 y=814부터이며 상단 퀵메뉴도 피해야 합니다. 그림은 전체 16:9로 표시되고 대사창 뒤로 이어질 수 있습니다.
4. LD-01은 2026-11-04 사용자 스케치에 따라 로만·시아·오므·다림·하린이 같은 흰색 프릴 드레스를 입고 햇빛 아래 잔디밭에 나란히 누운 구도입니다. 주인공은 등장하지 않습니다. 완성 그림은 `images/cg/ld_01_main_visual.webp`에 있으며 상단 로고와 하단 메뉴 사이로 다섯 얼굴이 보입니다. 원본·프롬프트는 `artwork/title_backgrounds_20261104/`에 보존했습니다.
5. 실제 대사·이름·번역 문구는 그림에 넣지 않습니다. 그림에 배경이 있어도 되고 투명 배경도 가능하며, 투명 영역 아래에는 옅은 파스텔 바탕이 표시됩니다.
6. LD는 표정과 감정·장면의 여운을 보여 주는 큰 그림입니다. 개그용 SD와 혼합하지 않고, SD 제작 명세는 [SD_EVENT_ASSET_GUIDE.md](SD_EVENT_ASSET_GUIDE.md)를 따릅니다.

## 데이터와 API

`game/data/cg_registry.json`에 `tabs`, `order`, `items`가 있으며 `items`에는 title, chapter, chapter_number, scene, priority, image, description, color, replay_label이 있습니다. 실제 대사는 기존 route 파일에 유지합니다. `game/data/cg_registry.rpy`는 init -11에 데이터를 읽고 `game/systems/cg_system.rpy`는 기존 init -20의 legacy cg_asset보다 나중인 init -6에서 API를 정의합니다. 갤러리 화면은 init offset 900으로 기존 테마의 갤러리를 대체합니다.

```renpy
$ cg_start("ld_02")
# 기존 네이티브 대사들을 이 사이에 유지합니다.
$ cg_end()
```

- `cg_asset(id)` → 실제 경로 또는 None. `LD-02`처럼 대문자·하이픈 표기도 정규화합니다.
- `cg_start(id, transition=None)` → LD를 한 장 표시하고 실제로 본 장면을 수집합니다. 시작 직전 일반/감정 모드·출연자·표정·위치·방향·master 이미지 속성과 ATL을 보관합니다.
- `cg_end(transition=None, restore=True)` → 원래 화면을 복원합니다. 새 배경으로 넘어갈 때는 `restore=False`를 사용합니다.
- `cg_is_active()` → LD 표시 중인지 확인합니다. 개별 스탠딩 렌더·화자 자동 추가는 LD 중에 차단해야 합니다.
- `cg_unlock(id)` / `cg_seen(id)` → 수집 등록·조회입니다. 메인 LD-01은 메인 메뉴 방문 때만 해금하며, 다른 LD는 해당 장면에서 cg_start를 실행해야 열립니다.
- `cg_unlock_sd(event_id, variant="01")` → 실제 본 SD 변형만 SPECIAL에 등록합니다. SD 시작과 변형 전환에서 호출하며, 갤러리를 여는 것만으로 등록하지 않습니다.
- `cg_restore_after_load()` → 활성 LD 화면을 저장 상태에서 복원합니다. after_load callback에 등록되어 있습니다.

### 표정 컷을 갤러리 한 칸에 묶기

각 컷은 기존처럼 별도 `items` 항목과 본편 `cg_start()` 호출을 유지합니다. 대표 항목에 아래처럼 `gallery_variants`를 표시 순서대로 넣고 `order`에는 대표 ID만 추가합니다. 후속 CH05·루트에도 같은 방법을 사용할 수 있습니다. 아직 없는 후속 그림이나 표정을 자동 생성·추정하지 않습니다.

```json
"ch04_private_roman": {
  "gallery_variants": ["ch04_private_roman", "ch04_private_roman_shy"]
}
```

위 예시는 기존 대표 항목에 추가하는 필드입니다. 나머지 `image`, `kind`, `tab` 등의 필드는 유지합니다. 같은 그룹의 모든 컷은 같은 종류·히로인 탭에 등록합니다. 대표 ID를 포함하며, 배열의 순서가 감상 순서입니다. `order`에 변형 ID를 실수로 함께 넣어도 한 칸으로 합칩니다. `settings.variant_transition`으로 표정 전환 시간을 바꿉니다.

- `cg_gallery_key(id)` → 표정 ID의 대표 장면 ID.
- `cg_gallery_variants(id, unlocked_only=False)` → 등록된 표정 목록. `True`일 때 수집한 컷만 반환.
- `cg_gallery_seen(id)` / `cg_gallery_preview(id)` → 한 컷이라도 수집했는지 / 첫 수집 컷 ID.
- `cg_unlocked_ids()` / `cg_adjacent()` → 갤러리의 장면 단위 수집 목록과 이동. `cg_seen()`은 계속 개별 컷 단위로 동작합니다.

갤러리의 표정 전환은 본편 `cg_current`와 영구 수집 집합을 변경하지 않습니다. 기존 저장 데이터의 컷 ID를 변환하거나 지울 필요가 없습니다.

### CH04 표정 컷의 구도 맞춤

CH04 다섯 개인 이벤트의 첫 컷과 두 번째 컷은 원본 화면 비율과 구도가 조금씩 다릅니다. 기존의 각 이미지별 `cover` 맞춤은 7:4 두 번째 컷을 약 1.6% 더 확대했습니다. 각 컷의 `screen_crop`에 공통으로 보이는 영역을 등록하고 `cg_displayable(id, size=(1920,1080), thumbnail=False)`로 표시합니다. 본편·갤러리 전체 보기·썸네일은 같은 보정 영역을 사용합니다. 이 필드가 없는 다른 CG의 표시 방식은 기존과 같습니다.

`screen_crop`은 원본에 대한 `[왼쪽, 위, 너비, 높이]`의 **0~1 비율 좌표**입니다. 해당 영역을 먼저 자른 뒤 같은 출력 화면에 맞춥니다. 보정은 회전 없이 작은 배율·위치 차이만 맞추며, 가장 크게 줄인 한쪽 가장자리도 약 1.67%입니다. 원본 이미지 파일은 수정하지 않습니다. 다른 구도의 그림으로 교체하면 이 좌표도 다시 맞춰야 합니다. 같은 구도로 더 큰 해상도의 그림을 교체할 때는 비율 좌표를 그대로 쓸 수 있습니다.

두 번째 PNG 원본은 1344×768로 첫 컷 2048×1152보다 작습니다. 화면 비율·구도 보정은 전환 시 확대감을 줄이지만 원본에 없는 세부 묘사나 선명도를 만들어 내지는 않습니다. 첫 그림을 일부러 흐리게 하거나 해상도를 낮추지 않습니다. 원본 크기·기준점 비교와 보정값은 [구도 분석 기록](../design_docs/cg_alignment_20261107/README.md)에 있습니다.

추가 요청에 따라 **두 번째 컷 다섯 장은 원본 비율을 유지해 2배 보간 확대**했습니다. 로만·다림·오므·하린은 2688×1536, 시아는 3318×1896입니다. 얼굴·표정·손·의상·배경을 새로 그리지 않는 Lanczos 보간이며, 별도 선명화·노이즈 제거·색 보정은 사용하지 않았습니다. 원본은 그대로 두고 `images/cg/upscaled/<컷 ID>_2x.png`를 등록했습니다. `fallback_image`는 같은 표정의 원본으로 연결하므로 확대본이 없더라도 재생됩니다. 정규화된 `screen_crop`은 같은 비율의 확대본에도 동일하게 적용됩니다.

생성형 확대 시험 결과는 얼굴과 선이 달라져 적용하지 않았습니다. 채택한 보간 확대는 원본 축소 비교 유사도 0.9987 이상, 기준점의 원본 좌표 이동 중앙값 약 0.03픽셀로 확인했습니다. 픽셀 수를 늘리는 보간이며 누락된 원화 디테일을 복구했다는 의미는 아닙니다. [확대본과 검증 기록](../artwork/ch04_upscale_20261107/README.md), [게임 등록 목록](../design_docs/cg_alignment_20261107/upscale_applied.json)에 경로·원본 해시·비교 수치를 보관했습니다.

최종 확대본을 연결한 뒤 다섯 쌍의 본편·갤러리·썸네일·저장 복원 검사 3개(검증문 46개)와 Lint를 통과했습니다. 실제 엔진이 확대된 파일을 읽는지, 보정 영역과 1920×1080 표시 크기가 유지되는지 확인했습니다. 원본 11개는 해시가 동일합니다. [최종 실행 검증 기록](../tests/cg_alignment_20261107/README.md)에 화면과 실제 로드 크기를 보관했습니다.

수정된 개발분 CH01~CH05는 Windows 배포판 `dist/20261107_final/CampusRomance-0.3.0-20261107-win.zip`으로 만들었습니다. 실제 배포 EXE의 시작·갤러리·저장/불러오기와 인자 없는 일반 실행을 별도 검사 폴더에서 확인했습니다. [배포·실행 검증 기록](../tests/distribution_20261107/README.md)에 압축파일·실행 파일 경로와 포함 파일 검증을 정리했습니다.

## 저장·구형 컬렉션 호환

현재 표시 중인 LD와 복원용 상태는 일반 세이브에 들어갑니다. 수집은 `persistent.cg_seen`, SD 변형 수집은 `persistent.cg_sd_seen`에 유지됩니다. 기존 `persistent.gallery`, `persistent.endings`와 모르는 이전 CG 키를 삭제하거나 초기화하지 않습니다. 이전 `festival_note` 수집은 SPECIAL에서 계속 볼 수 있습니다. 새 CG가 아닌 예전 메모 수집을 근거로 LD-02를 임의 해금하지 않습니다.

짧은 컷마다 디스크에 강제 저장하지 않고 영구 집합에 변경을 기록합니다. 기존 챕터 완료와 엔진의 종료 저장에서 영구 데이터를 보관합니다. 되돌리기를 해도 이미 본 CG의 영구 수집은 일반 게임 저장과 별도로 남는 VN 갤러리 동작입니다.
